## 2. 前回の審査の振り返り（2026-10-06）

**何が起きたか**
- 結果は「**Guideline 2.1 - Information Needed**」。アプリの欠陥で落ちたのではなく、**審査の履歴が少ない新しい開発者アカウントに出る、追加情報の依頼**。
- 求められたのは 6 つ: ①実機の画面録画（起動から、登録・ログイン・削除を含む）②目的と対象 ③使い方とログイン情報 ④外部サービスの一覧 ⑤地域の違い ⑥規制業種・他社の素材。
- あわせて「よくある問題」として、実機での不具合（2.1）、審査用アカウント（2.1）、スクリーンショットが本物の画面か（2.3.3）、課金の商品（3.1.1）が挙げられた。

**なぜ止まったままか**
- 返信の下書きは 10/6 に作ったが、そのあとアプリを大きく作り直した（撮影の流れ・図鑑・ホーム・設定など）ため、返信も録画も**古い版のままでは出せなくなった**。
- 今回は、**今の版に合わせて全部作り直した**（`review-reply.md`・`review-notes.en.txt`・説明文）。

## 3. 公開までの順番

```
① 不具合の修正（別の作業。PR #23）が終わる → main に入る
② iOS release で TestFlight へ送る → 実機で一通り確かめる
③ 決めること（下の 5）を決める → 配信国を直す・繁体字のページを消す
④ App Store Connect の文言を入れる（App Store metadata ワークフロー）
⑤ スクリーンショットを撮って入れる
⑥ 審査用アカウントを今の版で整える
⑦ 画面録画を撮る
⑧ 版 1.0.0 のビルドを新しいものに差し替える
⑨ 返信を送る（本文＋録画）・Notes を入れる → 審査に出し直す
⑩ 審査（たいてい 1〜3 日）→ 通ったら公開
```

### 実機で確かめること（2 の時）

- 起動してログインできる（ウェルカム画面の Google・Apple・「メールでログイン」）。「初めての方は 新規登録」で登録できる。ログアウト → もう一度ログインできる
- 初回に「AIへのデータ送信について」が出て、「同意して始める」で先に進める
- 物を撮ると、輪郭を光がなぞり、物の上に単語のタグが出る（**シミュレーターでは確かめられない所**）
- タグをタップ → ステッカーと単語と発音 → 図鑑に入る。輪郭が出ない写真でも、タップでお祝いの画面が開く
- 図鑑・単語のページ・発音・復習・ホームのアルバム・ウィジェット
- 設定 → アカウントを削除（**テスト用の別アカウントで**）→ ウェルカム画面に戻る
- 機内モードで撮る → 「解析待ち」に残り、通信が戻ると続きができる
- 落ちる・止まる・押しても反応しない所が無い
- **iPad でも**起動して一通り動く（iPhone 用アプリとして拡大表示で動く。審査の担当者が iPad で試すことがある。審査基準 2.4.1）
- Apple でサインインしたアカウントを削除できる（Apple との連携の解除まで。Web 版で 10/5 のデータベースの変更 `20261005120000_apple_tokens_client_id.sql` を Lovable で実行済みであること）

## 5. 決めてほしいこと

1. **配信する国**（`store-answers.ja.md` 3）
   - おすすめ: 中国本土（CHN）を外す。中国本土は ICP（政府への届け出番号）が無いと配信されず、AI（Google）も中国からは使えない。
   - EU: 配信するなら「デジタルサービス法」の**事業者の申告**が要り、事業者だと住所・電話・メールが EU の App Store に公開される。公開したくなければ EU の国を外す。
2. **繁体字中国語の App Store ページを消すか**（`store-answers.ja.md` 6）
   - PR #23 で、どのアカウントも台湾華語を学び、表示は日本語か英語だけになった。繁体字のページを読む台湾・香港の人は、今のアプリの対象ではない。今の繁体字のページの説明文も古い（「台灣華語・英語・日語に対応」）。
   - おすすめ: **繁体字のページを消す**（日本語・英語のページだけにする）。消した後、繁体字の設定の人には日本語のページが出る。台湾（TWN）の配信は残す（台湾に住む日本語・英語の人が対象）。
   - `ios/metadata` からは繁体字のファイルを消した（ワークフローで古い文言を入れ直さないように）。App Store Connect のページを消すのは画面から（ワークフローでは消さない）。残す場合は、今のアプリに合う繁体字の文を Claude が作り直す。
3. **新しい文言を App Store Connect に入れてよいか**（4）
   - 文言は `ios/metadata/` にある。この PR の「試すだけ」の実行結果（ci-previews の `runs/store-metadata/plan.md`）で、今の文言から何が変わるかを見られる。
   - よければ、Actions →「App Store metadata（文言を入れる）」→ apply にチェックして Run workflow。Claude に「入れて」と頼めば代わりに実行する。

## 6. Rork Max の使いどころ

**分かっていること（検索で確かめた範囲。Rork のサイトはこの環境から開けないので、細部は Rork の画面で確認してほしい）**
- Rork Max は、Rork から App Store・TestFlight に送れる（Apple ID で一度ログインした後は数クリック。署名も Rork が行う）。
- **AI App Store Reviewer**: 提出の前に、安全・性能・ビジネス・デザイン・法務の 5 つの面からアプリを点検し、却下されそうな所と直し方を出す。結果は見込みで、保証ではない。提出を止めることはない。「Fix」を押すと Rork の AI がコードを直す。
- **Screenshot Studio**: App Store 用のスクリーンショット画像（見出しと端末の枠つき）を作る。
- 説明文・キーワード・プライバシーの答えなど、App Store Connect の情報を考えるのは自分（Rork の比較ページの説明）。

**このリポジトリでの Rork の記録**
- 10/4 に Rork が説明文を App Store Connect に入れ、スクリーンショット（`screenshots/`）を作り、ビルド 1015 を審査に出した。
- Rork は main に直接書き込む（PR や自動チェックを通らない）。最後は 10/9。

**おすすめの使い分け**

| やること | おすすめ | 理由 |
|---|---|---|
| ビルドを TestFlight に送る | GitHub の `iOS release` | 1016〜1022 で動いている。中身が main と必ず同じ |
| 提出前の点検 | **Rork の AI App Store Reviewer を一度回す**（おすすめ） | 別の目で見る。指摘は Claude に見せて、本当に直すべきか一緒に確かめる |
| 点検の「Fix」 | 押さない（押すなら Claude に PR で見せてから） | Rork が main を直接書き換え、自動チェックを通らないため |
| スクリーンショット | 自分の iPhone で撮った画面を、Screenshot Studio で見出しつきに仕上げる、でもよい | 中の画面が今の版の本物であること（2.3.3）。Rork のプレビューの画面は main と違う恐れがある |
| 文言を入れる | `App Store metadata` ワークフロー、または Rork | どちらも `ios/metadata/` の同じファイルを読む。両方で別々に直さない |
| 審査に出す・返信 | App Store Connect の画面（自分） | 返信と録画の添付は画面からする |

### Rork に頼む時の文（コピーして使う）

- 点検だけ頼む:
  「App Store Reviewer を実行して、指摘をすべて一覧で見せて。コードや App Store Connect の設定は変えないで。」
- 見出しつきのスクリーンショットを作る（自分で撮った画像を渡す）:
  「Screenshot Studio で、渡した 6 枚の画面を使って App Store 用のスクリーンショットを作って。画面の中身は変えないで。日本語の見出しは：①撮るだけで、物に単語が付く ②言い方を選んで覚える ③自分の写真で図鑑 ④台湾の発音で聞く ⑤自分の写真で復習」
- Rork から出た指摘や画像は、Claude に見せる（本当に直すべきか、今の版と合っているかを確かめる）。

## 8. 言葉の意味

| 言葉 | 意味 |
|---|---|
| **審査（App Review）** | Apple がアプリを App Store に出してよいか確かめること。1〜3 日ほど |
| **Guideline（審査基準）** | Apple の決まり。番号（2.1 など）で呼ぶ |
| **Information Needed** | 「追加の情報がほしい」という連絡。却下とは違い、返信すれば続きが進む |
| **ビルド** | アプリを組み立てた 1 回分。番号（1022 など）が付く |
| **TestFlight** | 公開前のビルドを自分の iPhone に入れて試す仕組み |
| **メタデータ（文言）** | App Store に出る名前・説明文・キーワード・画像など |
| **審査メモ（Notes）** | 審査の担当者だけが読むメモ。使い方やログインの説明を書く |
| **配信国** | アプリを出す国・地域。App Store Connect の「価格と配信状況」で選ぶ |
