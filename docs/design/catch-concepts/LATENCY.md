# ラグを限界まで短くする設計（実装メモ）

撮影から図鑑に入るまでと、単語の詳細を開いたときに、ユーザーが何もできずに待つ場所をコードから洗い出しました。そのうえで、待ちを減らす方法を効果の大きい順に並べています。
数字のうち「今」はコードの設定値・目標値・品質メモから読んだ範囲です。「設計後」は見込みで、まだ計測していません。
サーバーは AI 呼び出しごとの所要時間を `ai_runs` に記録しているので（`src/lib/ai.functions.ts:188-230`）、改善の前後をここで測ります。

パスの表記は次のとおりです。

- iOS = `ios/CatchWords/`（このリポジトリ）
- Web = `nori-creator/lovable-catch-words-app`

## 1. 図鑑への追加を単語カードの生成から切り離す（効果：数秒〜10秒以上）

- **今**：「図鑑に追加」ボタンは、切り抜きと単語カード（`generateCard`）の両方を待っています（iOS `Views/CaptureView.swift:505-517`、`Views/CatchCelebrationView.swift:153-157`）。
  - カード生成にはサーバー側の時間の上限がありません。
  - 形の作り直しと「extras が空」のやり直しで、最大3回呼び出します（Web `src/lib/ai.functions.ts:932-974`）。
- **設計**：図鑑の枠に必要なのは、ことば・読み・意味・カテゴリー・切り抜きです。これらは候補（`suggestWords`）の時点でそろっています。
  - 先に仮の項目を入れて着地の演出を始めます。仮の項目の仕組み自体は今もあります（`CaptureView.swift:518-546`）。
  - カード生成は裏で続けます。図鑑の表示も保存も、カードを待ちません。
- **図鑑の枠とのつなぎ**：言い方の候補のどれを選んでも、同じ物の枠に入るようにします。
  - 候補の `group` で束ねます。
  - 図鑑の項目は束の中のふだんの言い方（`register: common`）で照合します。

## 2. 発音を先読みする（効果：最大2.5秒 → 0）

- **今**：選ぶ画面のタグには発音ボタンがありません。そのため、最初に音声を取りに行くのはお祝い画面です（iOS `Services/SoundService.swift:176-310`、`Views/CandidatePickerView.swift:356-357`）。
  - キャッシュがないと最大2.5秒待ち、そのあと端末の声に切り替わります。
- **設計**：
  - 候補が届いた時点で、各物のふだんの言い方の音声を先に取りに行きます（3〜5語）。
  - 選ぶ画面を開いたら、ほかの言い方も取りに行きます。
  - 同時に取りに行く仕組み（in-flight の共有）は、今の `SoundService` にあります。
- **サーバー**：
  - キャッシュがあるときは、署名付きURLを返したあとにもう一度取りに行く2往復になっています（Web `src/lib/tts.functions.ts:121-126`）。音声を直接返すか、CDN の公開URLにして1往復にします。
  - キャッシュがないときは base64 で返しています（`:192-194`）。ストリーミング（ElevenLabs の `/stream`、Gemini TTS のストリーミング）で、届いた分から鳴らします。

## 3. 持っている単語かの確認を先に済ませる（効果：タップのたびの待ち → 0）

- **今**：タグをタップすると `checkOwnedWord`（データベースの確認、時間の上限15秒）が走ります。その間、選ぶ画面は暗くなり、くるくる表示で操作できません（iOS `Views/CandidatePickerView.swift:57-62`）。
- **設計**：候補が届いた時点で、全候補をまとめて1回で確認しておきます。タップした瞬間に選ぶ画面を出します。

## 4. 候補を1件ずつ届ける（効果：最初の名前が出るまで 2.5〜8秒 → 見込み1〜2秒）

- **今**：結果は全部そろってから1つの JSON で返ります（Web `src/lib/ai.functions.ts:335-348`）。
  - 画像は data URL として、サーバー関数の JSON に入れて送っています（`:344`）。
  - 温度・出力の上限・推論の設定は、すべて初期値のままです。
- **設計**：
  - **1件ずつ受け取る**：AI SDK 6 の `streamText` + `Output.array()` の `elementStream` で、1件ずつ受け取ります（https://ai-sdk.dev/docs/ai-sdk-core/generating-structured-data）。Gemini の構造化出力は、途中まででも正しい形の JSON で届きます（https://ai.google.dev/gemini-api/docs/structured-output）。iOS へは、届いた物から順に送ります（SSE など）。
  - **画像の解像度設定を下げる**：Gemini 3 の `media_resolution` を LOW（280トークン）か MEDIUM（560）にします。初期値は約1120トークンで、入力が減るぶん速くなります（https://ai.google.dev/gemini-api/docs/media-resolution）。ただし、名前の正確さを必ず比べてから決めます。
  - **出力を絞る**：1件あたりの項目を、タグと選ぶ画面に必要な分だけにします。
  - **推論**：Flash-Lite 3.x は初期値が MINIMAL なので、このままにします（https://ai.google.dev/gemini-api/docs/thinking）。
- **端末側**：前景の切り抜き（`VNGenerateForegroundInstanceMaskRequest`）は今も同時に走っています（iOS `ViewModels/CaptureViewModel.swift:80-153`）。その結果を、名前より先に輪郭として描きます（動画の「下書き」）。

## 5. 単語カード（詳細の解説）を速くする（効果：見込み 5〜15秒 → すぐ開けば2〜6秒、あとで開けば0）

- **推論の深さを下げる**：`generateCard` は推論の設定なしで `latest-flash` を呼んでいます（Web `src/lib/ai.functions.ts:812-813, 875`）。最新の Flash は初期値が medium です（https://ai.google.dev/gemini-api/docs/latest-model）。
  - `providerOptions` で `reasoningEffort: "low"` を渡します。
  - プロバイダーは `@ai-sdk/openai-compatible` で、`reasoning_effort` として送られます。
  - 3.x では推論を完全には切れません。
- **AI を呼ぶ前の読み込みを同時にする**：約10回の読み込みが順番に待っていますが、どれも互いの結果を使っていません（`:660-683`、`isProUser` は `:812`）。
  - 同意の確認は先に行います。
  - 残りは `Promise.all` にするか、1回の select にまとめます。
- **作り直しを防ぐ**：出力の形を指定して（構造化出力）、形の作り直し（`:934-948`）を不要にします。
- **項目ごとに届ける**：例文 → 使い方 → 豆知識の順で流し、届いた項目から清書します。今は全部そろってから一度に表示しています（iOS `Views/WordDetailView.swift:310-313`）。
- **先に作っておく**：図鑑に入った直後から裏で生成しておきます。多くの場合は、あとで開くので待ちがなくなります。
- **共有キャッシュ**：例文や豆知識は人によって変わらない部分が多いので、同じ単語・同じ表示言語なら共有キャッシュにできます。今は `generated_cards` は記録のためのもので、キャッシュとしては読んでいません（Web `src/lib/generated-cards.ts:1-33`）。

## 6. 通信と準備を先に済ませる（効果：最初の通信で数百ミリ秒）

- カメラを開いた時点で、サーバーとの接続を作っておきます（事前接続）。
- 切り抜きの AI モデルを小さな画像で一度動かして、準備させておきます。
- 効果音（`prepareToPlay`）と振動（`CHHapticEngine` の起動）を先に用意しておきます。
- 撮影直後から写真本体の保存を始めます。今は切り抜きのあとに始めています（iOS `Views/CaptureView.swift:100-107`）。

## 7. 演出そのもののラグ

- 演出中も次のタグを押せるようにします。押したら、今の演出を早送りします。
- 大きな演出は、最初の1語・コンプリート・節目だけにします。ふだんは短い演出にします。
- 「視差効果を減らす」の設定がオンのときは、短い演出にします。

## 待った時間ごとの見せ方（下書き → 清書）

| 待った時間 | 見せ方 |
|---|---|
| 0.3秒まで | 何も出さない |
| 0.3〜1秒 | 下書きを始め、届いたらすぐ清書（最低0.4秒は見せる） |
| 1〜5秒 | 分かったことから描き、状態を一言で |
| 5〜10秒 | 「もう少しで書き終わります」。届いた項目から清書 |
| 10秒以上 | 「時間がかかっています。できたらお知らせします」。図鑑には入れたまま操作を続けられる |
