# CatchWords Web 版・Android 版 公開品質スコア — 採点基準（厳格版）

元にしたもの: `rork-catchwords-728/docs/launch-audit/RUBRIC.md`（iOS 版）。同じ減点の決まりを、
Web（https://catchwords.lovable.app）と Android（Capacitor の殻 `android/`・`.github/workflows/android-apk.yml`）に当てる。

## 採点のルール（iOS 版と同じ）
- 採点は**修正をした担当とは別の担当**が、毎回まっさらな状態で行う。
- 根拠は一次情報のみ: コード（file:line）、CI の結果（run id・job log）、本番サイトの画面写真
  （Playwright の Android 端末の再現）、Google Play / Android / 法令の公式文書。
  推測で点を与えない。**確認できないものは 0 点**。
- 各項目は満点から減点する。指摘 1 件ごとに:
  - **Blocker**（審査で落ちる・ビルドできない・クラッシュ・データ消失・法令違反・中心の流れが動かない）: その項目は 0 点
  - **Major**（主要な流れが壊れる・明らかに変な見た目・誤った表示）: 項目満点の 50% 減
  - **Minor**（細かい崩れ・文言・まれな不具合）: 項目満点の 20% 減
  - 項目は 0 点未満にならない。
- **後退（リグレッション）**: 前回の採点以降のコミットで新しく生まれた問題は、重さを 1 段上げて数える。
- **CI が赤**（Web の CI、または Android APK のビルド）のときは A の該当項目を 0 点にし、総合点の上限を 80 とする。
- オーナーしかできない作業（Play Console の登録・データセーフティ・署名鍵・運営者情報・実機確認）も
  **点から除外しない**。ただし「オーナー作業」と明記して分ける。
- Android の実機・エミュレータが無い場合、WebView 固有の挙動（カメラ・マイク・戻るボタン・OAuth）は
  コードと公式文書からの判断とし、実機で確かめられていない部分は点を与えない。

## 項目（合計 100）

### A. ビルドとテスト（15）
- A1 Web の CI（型・lint・翻訳検査・単体テスト・ビルド）と実物確認（real-app-check）が最新の main で緑（5）
- A2 Android APK のビルド（android-apk.yml）が最新の main で成功している（5）
- A3 ストア提出用の**署名付き AAB** を作る手段があり、実際に作られている（5）

### B. ストアとポリシー（25）
- B1 対象 API レベル: 2026-08-31 以降の新規アプリ・更新は **Android 16（API 36）以上**
  （developer.android.com/google/play/requirements/target-sdk）。compileSdk・minSdk・AGP・Gradle の整合（4）
- B2 権限の妥当性と説明: マニフェストの権限が実際の機能と一致し、不要な権限が無い。実行時の説明（4）
- B3 データセーフティ（Data safety）フォームの回答が実際のデータの扱いと一致（Play Console・オーナー作業）（4）
- B4 アカウント削除: アプリ内で削除できる＋**アプリを入れていなくても削除を求められる Web の URL**
  （Play Console の「アカウント削除」欄）がある。サーバー側のデータも消える（5）
- B5 生成 AI のコンテンツ方針: 不快な AI 出力を利用者が報告できる。外部 AI へのデータ送信の説明・同意（3）
- B6 ファミリー・子ども: 対象年齢の設定と、13 歳未満の扱いがポリシー・規約・Play の対象年齢と一致（2）
- B7 Web/PWA: manifest・サービスワーカー・インストール可能性・HTTPS・Play の課金規約（アプリ内で Web 課金へ誘導しない）・AdSense を WebView に出さない（3）

### C. Android での機能（20）
- C1 中心の流れ（はじめる→チュートリアル→撮影→AI→カード→図鑑）がモバイル Chrome と Capacitor WebView の両方で動く（6）
- C2 **ログイン**: メール・Google・Apple が WebView で完結する
  （Google は埋め込み WebView での OAuth を拒否する: `disallowed_useragent`）（5）
- C3 端末の機能: カメラ（file input の capture／ネイティブカメラ）・位置・マイク・音声再生・通知（4）
- C4 戻るボタン・ディープリンク（`catchwords://`）・外部リンク・アプリ切り替え後の復帰（3）
- C5 公開画面のボタンがすべて反応し、何も起きないボタンが無い（2）

### D. 見た目と使いやすさ（15）
- D1 ja / en / zh-TW の全公開画面で、はみ出し・重なり・切れ・言語の混ざりが無い（Pixel 7 と 360×640）（6）
- D2 ダークモード・小さい画面・文字の拡大で崩れない（4）
- D3 タップ領域 48dp（Android の推奨）／44px、入力欄 16px 以上（拡大されない）、セーフエリア（3）
- D4 本番に開発用の表示（例: 「Edit with Lovable」バッジ）が出ていない、統一感（2）

### E. 安定性と性能（10）
- E1 コンソールのエラー・ハイドレーション不一致・読み込み失敗が無い（5）
- E2 中級 Android 端末での重さ: 読み込む JS・画像・3D・フォントの量、繰り返しの通信、止まらないタイマー（5）

### F. 法務とデータ（15）
- F1 プライバシーポリシーが実際のデータの扱いと一致し、3 言語で公開されている（4）
- F2 利用規約・特定商取引法の表記が公開され、運営者情報が埋まっている（オーナー作業を含む）（4）
- F3 データの守り: 利用者データを持つ全テーブルに RLS、ストレージの公開/非公開が妥当、ログに個人情報を残さない（4）
- F4 削除・保存期間・同意（外部 AI への送信・広告・位置）（3）
