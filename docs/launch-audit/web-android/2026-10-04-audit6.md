## Android ビルドの診断と直し方

### 何が起きていたか（一次情報）
- `android-apk.yml` の実行: run 6（997968a, 9/13）〜 run 10（636ffb3, 9/29）の 5 回すべて `failure`。失敗した段は 5 回とも「依存パッケージを入れる」（`npm ci`）。
- run 10 の job 109385089976 のログ:
  ```
  npm error `npm ci` can only install packages when your package.json and package-lock.json ... are in sync.
  npm error Missing: @capacitor/haptics@8.0.2 from lock file
  npm error Invalid: lock file's @lovable.dev/vite-tanstack-config@2.13.1 does not satisfy @lovable.dev/vite-tanstack-config@2.23.1
  npm error Missing: drizzle-kit@0.31.11 / drizzle-orm@0.45.3 / postgres@3.4.9 / three@0.186.1 ... from lock file
  ```
- **根本の原因**: Lovable は bun（bun.lock）で依存を足すので、package-lock.json が取り残されていた。lock は 4cde207（10/03「package-lock.json を package.json・bun.lock と同じ版にそろえる」）で直り、CI（ci.yml の `npm ci`）は緑。だが android-apk.yml の `paths` は `android/**`・`capacitor.config.ts`・ワークフロー自身だけで、**package.json / package-lock.json が変わっても走らない**。そのため直った後に一度も実行されていない。

### この監査環境で再現した範囲
| 段 | 結果 |
|---|---|
| `npm ci`（3bf12d2、Node 22.22 / npm 10.9） | **成功**（608 パッケージ） |
| `npm run build` | **成功**。`.output/public` ができる（`webDir` と一致） |
| `npx cap sync android` | **成功**。プラグイン 5 つ（app・camera・geolocation・haptics・local-notifications） |
| `./gradlew assembleDebug` | **再現できず**。Java 21 はあるが Android SDK が無く、dl.google.com（SDK・Google Maven）への通信がこの環境の方針で遮断されている |

設定の整合: AGP 8.13.0 + Gradle 8.14.3 + Java 21（Capacitor 8 の要件どおり）、compileSdk/targetSdk 36（GitHub の ubuntu-24.04 には SDK があり、足りない platform は AGP が取得する）。Gradle の段で落ちる要因はコードからは見つからなかった。**最後の確認は CI で 1 回走らせること**。

### 直し方（`android-fix.patch`、`git apply --check` で 3bf12d2 に当たることを確認済み）
1. `android-apk.yml`: `paths` に `package.json`・`package-lock.json` を追加（W-01）。`setup-java@v5`。`npm ci --no-audit --no-fund`。
2. 秘密 `ANDROID_KEYSTORE_BASE64`・`ANDROID_KEYSTORE_PASSWORD`・`ANDROID_KEY_ALIAS`・`ANDROID_KEY_PASSWORD` がある時だけ `bundleRelease` で**署名付き AAB** を作り、`catchwords-release-aab` として上げる。versionCode は `github.run_number`（W-02）。
3. `android/app/build.gradle`: 環境変数から読む `signingConfigs.release`、versionCode を `CW_VERSION_CODE` から。
4. `AndroidManifest.xml`: `catchwords://` の intent-filter（W-06、W-03 の前提）、RECORD_AUDIO・MODIFY_AUDIO_SETTINGS を削除（W-05）、`allowBackup="false"`（W-13）。

パッチだけでは W-03（Google/Apple のログイン）は直らない。Web 側で「アプリの中なら Custom Tabs で `/native-auth` を開き、`catchwords://auth-callback` で受けてセッションを入れる」処理（`@capacitor/browser` の追加、`App.addListener("appUrlOpen")` で `#access_token=…&state=…` を受け、state を照合して `supabase.auth.setSession`）が要る。

## データ管理のまとめ

- **RLS**: 移行で作られる 31 テーブル（ai_runs … words）すべてに `ENABLE ROW LEVEL SECURITY`。過去の `USING (true)` の書き込み（review_choices・words）は後の移行で取り消し済み（`review_choices_no_write`、`words_insert_auth` の削除）。共有の辞書系（dictionary_entries・word_explanations・generated_cards）は読み取りだけ公開で、利用者のデータは入らない。
- **ストレージ**: `tts` 非公開（共有の読み上げ音声）、`avatars` **公開**（本人のフォルダにだけ書ける。W-15）、`stickers` は自分のフォルダ＋見えてよい投稿だけ読める policy。バケット自体の作成は移行に無い（W-16）。
- **アカウント削除**（`src/lib/profile.functions.ts:287-358` `deleteMyAccount`）: stickers・avatars の自分のフォルダを消す → `words.created_by` を null に → 18 テーブルを明示的に削除 → `auth.admin.deleteUser`。明示の一覧に無い `entry_reports`・`model_shadow_predictions`・`user_shelves`・`wordbooks`・`wordbook_entries` は `auth.users` への `ON DELETE CASCADE` で消える。漏れは見つからなかった。Apple の許可の取り消しは保留中パッチ 0004。Stripe の解約は自動ではない（ポリシーに明記あり）。
- **保存期間**: 「アカウントがある間」。記録（usage_events・ai_runs・scan_events）を期限で消す仕組みは無い（W-18）。
- **ログの個人情報**: `console.*` でメール・トークン・プロンプトを出している所はコードからは見つからなかった。Cloudflare・Supabase 側の記録は確かめられない。
- **端末側**: `allowBackup="true"` で WebView のトークンがバックアップに載る（W-13）。
