# CatchWords 公開品質スコア — 採点基準（厳格版）

オーナー指示（2026-10-03）: App Store に公開できる状態にする。公平・冷静に評価し、完成度が 100 になるまで作業を続ける。
定期的に完成度を測り、変な修正をしたら点が下がるよう厳格に採点する。

## 採点のルール
- 採点は**修正をした担当とは別の担当**が、毎回まっさらな状態で行う（自分の修正を甘く見ないため）。
- 根拠は一次情報のみ: コード（file:line）、CI の結果（run id）、CI の画面写真（ci-previews ブランチ）、Apple / 法令の公式文書。推測で点を与えない。**確認できないものは 0 点**。
- 各項目は満点から減点する。指摘 1 件ごとに:
  - **Blocker**（審査で落ちる・クラッシュ・データ消失・法令違反）: その項目は 0 点
  - **Major**（主要な流れが壊れる・明らかに変な見た目・誤った表示）: 項目満点の 50% 減
  - **Minor**（細かい崩れ・文言・まれな不具合）: 項目満点の 20% 減
  - 項目は 0 点未満にならない。
- **後退（リグレッション）**: 前回の採点以降のコミットで新しく生まれた問題は、重さを 1 段上げて数える（Minor→Major、Major→Blocker）。
- **CI が赤**のときは A の該当項目を 0 点にし、総合点の上限を 80 とする。
- オーナーしかできない作業（法務情報の記入、App Store Connect、サーバー側の課金確認、実機確認）も**点から除外しない**。ただし「オーナー作業」と明記して分ける。
- 前回の採点ファイルと比べ、上がった項目・下がった項目と理由を必ず書く。

## 項目（合計 100）
### A. ビルドとテスト（15）
- A1 iOS check（ビルド・単体テスト）が最新コミットで緑（5）
- A2 全画面の自動テスト（FullTourTests）が最新コミットで緑（5）
- A3 TestFlight 配信（ios-release）が最新の main で成功している（5）

### B. App Store 審査ガイドライン（30）
- B1 2.1 完成度: 仮の文言・空の画面・押しても何も起きないボタン・テスト用の裏口が無い。審査用アカウントと審査メモがある（6）
- B2 5.1.1 プライバシー: 権限の説明文、プライバシーポリシーへのリンク（アプリ内・App Store Connect）、PrivacyInfo.xcprivacy が実際と一致、App Privacy の回答が実際と一致（6）
- B3 5.1.1(v) アカウント削除がアプリ内で完結し、サーバー側のデータも消える（4）
- B4 3.1.1 / 3.1.2 / 3.1.3 課金: 課金画面の表示要件（期間・価格・自動更新・規約とポリシーへのリンク・復元）、Web 購入の扱い（4）
- B5 4.8 ログイン・5.1.1 ログイン必須の妥当性（3）
- B6 2.3 メタデータ: アプリ名・説明・スクリーンショット・年齢区分・サポート URL（3）
- B7 2.5 技術要件: 非公開 API なし、IPv6、バックグラウンド処理の正当性、暗号化の申告（4）

### C. 機能の正しさ（20）
- C1 中心の流れ: 撮影→AI 分析→物を選ぶ→言葉を選ぶ→カード→図鑑（6）
- C2 復習・単語詳細・発音・設定（5）
- C3 通信切れ・失敗・権限拒否・ログイン切れで止まらず、写真を失わない（5）
- C4 アカウントの切り替え・サインアウト・削除でデータが混ざらない（4）

### D. 見た目と使いやすさ（15）
- D1 ja / en / zh-TW の全画面で、はみ出し・重なり・切れ・言語の混ざりが無い（CI 画面写真で確認）（6）
- D2 ダークモード・小さい画面（SE）・大きな文字設定で崩れない（4）
- D3 VoiceOver の基本（ボタンに名前がある）、タップ領域 44pt（2）
- D4 デザインの統一感、デモで決めた仕様（docs/prototype/SPEC.md）との一致（3）

### E. 安定性と性能（10）
- E1 クラッシュの原因になるコード（強制アンラップ、範囲外、メインスレッドの重い処理、競合）が無い（5）
- E2 メモリ・通信量・バッテリー（大きな画像、繰り返しの通信、止まらないタイマー）（5）

### F. 法務（10）
- F1 プライバシーポリシーが実際のデータの扱いと一致し、3 言語で公開されている（4）
- F2 利用規約（または Apple 標準 EULA の採用）と特定商取引法の表記が公開されている（3）
- F3 運営者情報など、オーナーが埋める項目が埋まっている（3）

## 採点ファイル
`docs/launch-audit/<日時>.md` に、総合点・項目ごとの点・指摘一覧（重さ、file:line、根拠）・前回との差を書く。
