### 今回の重点の確認（点を引いていないもの）

- **送信の列での行き詰まり（デッドロック）**: 無い。`reconcile` は `sendChain` を待つが、列の中の仕事（`sendPending` → `send` → `NativeAPI.call("recordAiConsent")`）は同期を待たない。`recordAiConsent` / `getAiConsent` は `aiFunctions` に無いので手前の門で止まらず、`NativeAPI.call` の 403 のやり直し（`NativeAPI.swift:69`）からも `recordFunctions` で外れる。AI の関数が 403 → `serverRefused` → `sync` → `reconcile` → 列を待つ、の順でも、列の側から同期や AI の関数に戻る道は無い。ターゲットは `SWIFT_DEFAULT_ACTOR_ISOLATION = MainActor`（project.pbxproj:537・579）なので、`sendChain`・`syncTask` の読み書きはすべてメインアクター上で、データ競合も無い。
- **列が伸び続けないか**: 各 Task は一つ前の Task を待つだけで、終わった Task はその場で値を返す。押した回数だけ小さな Task ができるが、押すたびに 1 つで、終わった後は何も走らない。繰り返しの通信は無い。`reset()` は `sendChain` を消さないが、前のアカウントの列の仕事は `send` の `SupabaseClient.shared.userId == uid`（`:315`）ですぐ nil になる（通信中だった 1 件だけ最大 15 秒待たされる。画面は待たない）。
- **今の本番サーバでの動き**: Web main 3bf12d2 は知らない関数に 404 を返す → `APIError.server(404, …)` → `send` が `catch { return nil }`（`:319-321`）、`getAiConsent` は `try?`（`:247`）。列の Task・同期の Task とも `RootView.swift:69` の待たない Task と `sendAnswer` の Task の中なので、画面は止まらず、エラーも出ない。未送信の印は起動ごとに 1 回送り直すだけ。
