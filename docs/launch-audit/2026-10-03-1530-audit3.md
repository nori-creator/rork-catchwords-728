### 今回の重点の確認（点を引いていないもの）

- **今の本番サーバでの動き**: Web main 3bf12d2 の `src/routes/api.native-fn.ts:28` は知らない関数に 404「その機能はありません。」を返す。`NativeAPI.post` は `APIError.server(404, …)` を投げ、`AIConsent.send` は `catch { return nil }`（`AIConsent.swift:304-306`）、`getAiConsent` は `try?`（`:236`）で黙る。同期は `RootView.swift:66-69` で待たない `Task` なので、画面は止まらず何も表示しない。未送信の印（pending）があれば起動ごとに 1 回送り直すだけで、無限の再試行は無い。本番は `AI_CONSENT_REQUIRED` の 403 を返さないので、403 の処理は今は動かない。
- **403 のやり直し**: `NativeAPI.swift:67-75`・`:115`。やり直しは 1 回だけで、2 回目の `post` はもう 403 を拾わない。`recordAiConsent` / `getAiConsent` は `recordFunctions` で除外され、同期の中から再び同期に入る循環は無い。Web パッチの `statusForError`（0003）は `AI_CONSENT_REQUIRED` を含むと 403、`publicMessage` は先頭を保つので、iOS の `hasPrefix` と合う。
- **同期と同意・取り消しの競合**: 同期の途中で同意・取り消しをすると、`getAiConsent` の後に `!Self.isPending(uid)`（`AIConsent.swift:238`）で捨てるので、古いサーバの答えで上書きしない。同じアカウントの同期は 1 本にまとまる（`:182`）。残る穴は R3-01（送信どうしの順番）だけ。
- **`AI-Consent-Version` 見出し**: 全呼び出しに付く（`NativeAPI.swift:95`）。今の本番は無視する。パッチ公開後は「見出しがあれば確かめる」ので、この版は移行を待たずに確かめられる側に入る。移行前（表が無い）はサーバが通す。
- **scripts/check_native_contract.py の PENDING_WEB_DEPLOY**: 2 つの名前だけを通し、他の知らない関数は今までどおり赤。Web に載ったら警告を出して普通に確かめる。Web main 3bf12d2 のローカルの写しで実行し、rc=0（36 件確認、2 件保留）。
